# 任务：生成《校园互助服务平台》用户故事 + 3.3 问题对比分析

> **使用模型：** Claude Opus 4.7（主）/ ChatGPT（对照）
> **关联交付物：** `docs/P1/用户故事.md`、`docs/P1/3.3问题.md`、`docs/P1/AI协作反思日志_P1.md`

---

## 1. 角色设定 (Role)

你现在是一名熟悉敏捷/Scrum 用户故事写法、且对高校 O2O 互助平台有真实使用经验的资深需求分析师。你需要把已经定稿的《软件需求规格说明书》和《调研原始数据》翻译成"可交付给开发 + QA"的用户故事与验收标准清单。

## 2. 任务目标 (Task)

1. 基于 `docs/P1/软件需求规格说明书.md` 的功能需求矩阵，与 `docs/P1/调研原始数据.md` 的问卷 + 访谈痛点，**显式定义 ≥ 15 个不同的用户角色**。
2. 为每个角色产出 **至少一条用户故事**，全文故事总数 ≥ 15 条（实际 20 条）。
3. 每条故事必须遵循 "**作为 [角色]，我希望 [功能]，以便 [价值]**" 的句式，并附：
   - 3 条以上**可测试**的验收标准；
   - **MoSCoW** 四级优先级（Must / Should / Could / Won't）；
   - 需求追踪（关联 SRS 中的 FR 编号）。
4. 输出一份对 AI 自身产出做的反向审查（见下方"对比分析"）。

## 3. 硬性约束 (Constraints)

- **场景贴合**：故事必须映射到问卷/访谈里的真实痛点（如"防社死""信息过载""恶意差评"），禁止生造校园不会出现的场景。
- **禁止复用 SSO**：本产品不依赖校方 SSO，所有涉及身份的故事必须使用"手机号 + 人工审核"机制。
- **禁止真实货币**：交易类故事的报酬字段只能用"积分"或"自定义文字描述（线下结算）"。
- **验收标准必须可测试**：使用类型、数量、时间、并发等量化指标；禁止"体验流畅""交互友好"这类模糊词。
- **覆盖 15 个角色**：不得把 2 条故事用在同一角色上以凑数；至少每个角色挂 1 条故事。
- **显式列出"本期不做"**：至少给出 1 条 `Won't` 项（本迭代不做但入 backlog），说明取舍理由。

## 4. 执行流程 (Workflow)

1. **角色矩阵构建**：通读 SRS / 调研资料，罗列潜在角色（发布者 / 接单者 / 管理员三类过于粗，需拆到"跑腿发布者、跑腿接单者、二手卖家、二手买家……"等细粒度）。
2. **痛点映射**：为每个角色打 2-3 个"核心诉求标签"，确保故事覆盖调研中高频痛点。
3. **故事编写**：按角色 × 诉求 × SRS FR 编号三方对齐，补齐验收标准。
4. **反向审查**：让 AI 扮演"测试工程师 + 校园运营"视角，从可测试性、异常流、隐私合规三个维度复核故事（产出进入 `3.3问题.md`）。

## 5. 输出规范 (Output)

- 标准 Markdown，含"角色矩阵表 + 故事列表 + MoSCoW 汇总 + 追踪矩阵"四个板块。
- 用 `[Must]` / `[Should]` / `[Could]` / `[Won't]` 直接写在故事标题尾部，便于 grep 筛选。
- 追踪矩阵以表格形式列出 `US-xx → FR-xx`。

## 6. Few-Shot 示例

> ### US-02 抢接跑腿单 `[Must]` — 角色 R02
>
> **作为** 跑腿接单者，
> **我希望** 点击"接单"按钮即能抢到任务并自动开启与发布者的私信窗口，
> **以便** 高效沟通、避免被其他人抢走。
>
> **验收标准：**
> 1. 列表页到接单成功的总点击次数 ≤ 3 次。
> 2. 并发场景（两人同秒点击）下有且只有一人成功，另一人收到"手慢了"提示，不产生重复订单。
> 3. 接单成功后 2 秒内，双方会话列表出现以任务标题命名的会话窗口。
> 4. 接单者进行中任务数 > 3 时，系统拒绝接单并提示"当前进行中任务已达上限"。

## 7. 反向审查 Prompt（用于 3.3 问题对比）

> **角色切换：** 你现在是负责该产品的**QA 工程师**。请重新阅读 `docs/P1/需求分析.md` 中 AI 生成的 UC-01 / UC-02 / UC-03 用例，并回答：
>
> 1. 每条"基本流程/替代流"是否足以直接转化为测试用例？字段类型、长度、并发阈值是否齐全？
> 2. 哪些"异常流"被 AI 完全遗漏？请举例并给出正确写法。
> 3. 与 `docs/P1/用户故事.md` 中同主题故事的验收标准相比，AI 原版缺失了哪些可量化要素？
>
> 输出要求：分"遗漏异常流""验收标准是否具体可测试""小结"三段，含**对比表格**。
