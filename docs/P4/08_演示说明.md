## 一、运行方式

### 1.1 前置依赖

| 依赖 | 版本 | 说明 |
|------|------|------|
| JDK | 17+（实测 21） | 后端 Spring Boot 3.5 |
| Node.js | 18+（建议 20 LTS） | 前端 Vite + React 19 |
| MySQL | 8.x / 9.x | 库名 `campushub`，`createDatabaseIfNotExist=true` 会自动建库 |

> ⚠️ 前端 `package-lock.json` 跨版本敏感，npm 报 lock 冲突时用 `node:20` 容器重装依赖（见组内约定）。

### 1.2 一键启动（推荐）

注：运行这个需要稍微等一会，等后端起来才能看到真实数据

```bash
# 根目录
./start.sh            # = ./start.sh local：mvnw spring-boot:run + vite dev
```

- **首次运行**会从模板生成 `backend/src/main/resources/application-local.properties` 并提示填 MySQL 密码：

  ```bash
  # 编辑该文件，把密码填进去（用户名默认 root）
  spring.datasource.username=root
  spring.datasource.password=你的MySQL密码
  ./start.sh            # 再跑一次
  ```

- 启动成功后：
  - 前端 **http://localhost:5173**
  - 后端 **http://localhost:8080**
  - 健康检查：`curl http://localhost:8080/api/health`
- **数据库无需手动建表**：Flyway 启动时自动应用 `V1 … V20` 全部迁移；`ddl-auto=validate` 校验实体与表一致。
- Windows 用 **Git Bash / WSL**（原生 CMD/PowerShell 跑不了 `.sh`）。

### 1.3 手动启动（不想用脚本）

```bash
# 后端
cd backend && ./mvnw spring-boot:run        # 默认 profile=local，读 application-local.properties
# 前端（另开终端）
cd frontend && npm install && npm run dev
```

### 1.4 启动成功的判断

后端日志出现：
```
Successfully applied N migration(s) ... now at version v20
Started CampushubApplication in X seconds
```
浏览器打开 http://localhost:5173 看到登录页即就绪。

### 2.2 一键灌演示数据 ⭐ `scripts/seed-dev.sh`

```bash
bash scripts/seed-dev.sh
```

脚本做的事：注册 3 个用户（注册即自动发 100 启动积分）→ 各自提交学生证认证 → **用内置超管 `admin/admin123` 走真实审核 API 一次性通过** → 发 **7 个任务 + 3 件二手商品**。产出：

| 演示账号（手机号） | 昵称 | 登录验证码 | 状态 |
|---|---|---|---|
| `13900000001` | 测试小明 | `123456` | 已认证，发了 3 个任务 + 1 件二手 |
| `13900000002` | 测试小红 | `123456` | 已认证，发了 2 个任务（含辅导）+ 1 件二手 |
| `13900000003` | 测试学长 | `123456` | 已认证，发了 2 个任务 + 1 件 Kindle |

- 任务覆盖三种类型：**跑腿 ERRAND**（取快递/带外卖）、**互助 MUTUAL_HELP**（搬宿舍/借计算器）、**辅导 TUTOR**（高数答疑/Python）。

## 三、核心演示路径

> 角色约定：**P/R** 为两个普通账号（用 §2.2 的测试小明 / 测试小红即可），**Admin** = `admin/admin123`。
> 建议开两个无痕窗口分别登 P、R，第三个登 Admin。

### 🚀 黄金路径（赶时间版，~6 分钟）

`seed-dev.sh` 灌数 → R 登录在**任务大厅**接小明的「取快递」单 → 传凭证 → 小明确认完成 → 双方互评 → R 举报小明 → Admin 后台扣信用分 → 小明信用分下降。一条线串起 **任务 + 评价 + 举报 + 信用 + 管理后台**。

下面按**模块**逐个介绍（演示时挑重点讲，每个 1~2 分钟）。

---

### 3.1 首页 + 智能匹配（recommend）
- **入口**：`/`（未登录可看）、登录后 `/app`。
- **看点**：首页聚合各模块入口；**智能匹配**对任务做规则加权打分排序（类型 / 取送位置 / 发布者信用 / 悬赏 / 新鲜度 / 紧急度），新用户冷启动会自动重分配权重。大厅列表即按推荐分排序。

### 3.2 学生认证 + 管理后台审核（auth + admin）
- **入口**：「我的 → 学生证认证」`/verify`；管理端 `/admin/verifications`。
- **演示**：新账号提交姓名/学号 + 证件图 → Admin 后台审核，**点缩略图灯箱看原图** → 通过 / 驳回（驳回填理由，被驳回者能在认证页重新提交）。
- **亮点**：学号**跨账号去重**（V19）——给第二个账号填同一学号提交 → 「该学号已被其他账号认证」。

### 3.3 任务模块 ⭐（task，四大模块之一）
- **入口**：`/app/tasks` 大厅、`/app/tasks/new` 发布、`/app/tasks/my` 我的任务、`/app/tasks/:id` 详情。
- **定位**：跑腿 / 互助 / 辅导三类悬赏任务，State 模式状态机驱动全流程。
- **全流程演示**：
  1. P 发任务 → 悬赏积分**冻结**（「我的 → 信用·积分」可见冻结）。
  2. R 接单 → 押金（悬赏 1/5）冻结；**流程进度条**：已发布 → 已接单。
  3. R 上传凭证（图 + 完成说明）→ 进度到「凭证已交」。
  4. P 确认完成 → 押金解冻、悬赏结算给 R，进度到「已完成」。
  5. 双方互评（1~5 星）。
- **可选看点**：接单上限（默认每日 2~3 单）、延长截止、自接禁止、并发抢单乐观锁、超时自动过期（5min 扫描）。

### 3.4 二手交易模块 ⭐（trade，四大模块之一）
- **入口**：`/app/trade` 大厅、`/app/trade/new` 发布、`/app/trade/mine` 我的交易、`/app/trade/:id` 详情。
- **定位**：闲置商品发布 + 议价 + 押金担保交易。
- **演示**：
  1. 卖家上架商品（如 seed 的「九成新 Kindle」）。
  2. 买家进详情：**立即购买** 或 **出价砍价**（买卖回合制 Ping-Pong 还价，轮到谁谁操作）。
  3. 成交后冻结押金，双方在「我的交易」**确认收货**（双向确认完成）。
- **亮点**：下单用乐观锁防「双买」；议价多轮通知去重。

### 3.5 辅导模块（edu，四大模块之一）
- **入口**：`/app/edu/tutor` 辅导大厅、`/app/edu/tutor/new` 发布。
- **定位**：辅导需求本质是 **taskType=TUTOR 的任务**，复用任务状态机与详情页，但走专属 URL/文案，顶栏高亮「辅导」。
- **演示**：发布一条辅导需求（如「高数 II 答疑」）→ 在辅导大厅按辅导类目浏览 → 接单流程同任务。
- **亮点**：**违禁词拦截**——标题/描述含 `兼职 / 代写 / 刷课` 等被拒（400 + 提示），24h 内命中 3 次进入冷静期。

### 3.6 组队模块（team，四大模块之一）
- **入口**：`/app/team` 大厅、`/app/team/new` 发起招募、`/app/team/:id` 详情。
- **定位**：竞赛 / 项目 / 活动找队友。
- **演示**：
  1. P 发起招募（标题 / 需求 / 名额）。
  2. R 在详情页**申请加入**（附一句留言）。
  3. P 在详情页**审批**申请（通过 / 拒绝）；满员或截止可**关闭招募**。

### 3.7 消息 / 私信模块（im）
- **入口**：`/app/im` 会话列表、`/app/im/:cid` 聊天；任务/二手详情的「联系」按钮一键开聊。
- **演示**：在二手详情点「联系卖家」→ 自动开会话并发一张**订单卡片**（可点回商品）→ 互发文字 / 图片。
- **亮点**：接单成功会自动建会话 + 系统消息；进会话即标已读，顶栏未读角标实时更新。

### 3.8 通知中心（notify）
- **入口**：顶栏铃铛 → `/app/notify`。
- **演示**：接单 / 完成 / 认证结果 / 举报裁决 / 申诉结果等都会推站内信；按 全部 / 未读 / 已读 分页。
- **亮点**：**点击通知即标已读**（含认证、举报等无跳转类型），可一键全部已读；有业务实体的通知点击直达详情。

### 3.9 个人主页 + 隐私（me + 公开主页）
- **入口**：`/app/me` 我的、`/app/me/edit` 编辑资料 / 隐私、`/u/:userId` 公开主页（对外）。
- **演示**：
  - 「我的」聚合：信用分 / 可用积分 / 冻结积分 / 日接单上限、任务统计、收到的评价、交易入口。
  - 编辑资料 + **隐私开关**（隐藏发布数 / 接单数 / 收到的评价）——开关后再看公开主页对应项显示「已隐藏」。
  - 公开主页 `/u/:id` 是别人眼里的你，**绝不暴露手机号 / 真实姓名 / 学号**（统一走 PublicUserVO）。

### 3.10 信用 · 评价 · 申诉（credit）
- **入口**：`/app/credit` 信用中心、`/app/credit/appeals` 评价 / 申诉。
- **演示**：
  - 信用分（0~120）+ 积分流水明细；< 60 禁发禁接。
  - 「我收到的评价」列表；对**差评（≤2 星）发起申诉** → Admin 后台通过则**撤销该差评**。
  - 撤销后「收到的评价」计数 **-1**；可对撤销的差评 / 已处理的申诉点**「删除」（二次确认）**，从自己列表隐藏。

### 3.11 举报 + 管理仲裁（report + admin）
- **入口**：任务 / 二手 / 用户主页的「举报」；管理端 `/admin/reports`、`/admin/users`、`/admin/appeals`。
- **演示**：
  - 用户举报（选类别 + 说明，类别是自定义下拉）。
  - Admin 仲裁：**扣信用分 / 警告 / 驳回**（全是应用内对话框，非浏览器弹窗）；扣分后被举报方信用分**正确下降**。
  - 用户管理：搜索、封禁 / 解封、超管可分派 / 取消管理员（敏感操作均二次确认）。

### 3.12 AI 助手（agent）
- **入口**：登录后任意页右下角浮窗「校园助手 🐾」。
- **定位**：接 DeepSeek 大模型的对话助手，能理解口语并调用四类工具：
  - ① 找任务/接单（search_tasks）② 发任务（draft_task 生成草稿，不自动发布）③ 找二手（search_trade）④ 找队友（search_team）。
- **演示**：输入「帮我找个取快递的单」→ 返回匹配任务卡片；「帮我发个明天取快递给 5 积分」→ 生成任务草稿待你确认。
- **亮点**：LLM 不可用时**规则降级**——仍按「找单」返回最新待接单任务，不白屏。

## 四、演示前修复的关键 Bug 日志

> 格式：现象 / 根因 / 修复 / 验证。完整 bug 记录见 `docs/P4/bug/`。本节只列**影响演示**的高优修复（2026-06-06~07）。

### Bug-17　被举报后信用分不降反升 🔴
- **现象**：管理员对举报「扣 10 分」，被举报方信用分反而 +10（如 100→110）。
- **根因**：`ReportServiceImpl` 调 `creditApi.deduct(uid, penalty, …)` 传**正数**；`CreditServiceImpl.deduct` 对未注册 reasonCode 直接用入参 delta，`adjustScore(+10)` → 加分。
- **修复**：扣分传负数 `deduct(uid, -penalty, …)`（deduct 按有符号 delta 处理）。
- **验证**：端到端实测，举报方初始 100 → PENALIZE 10 → **90** ✅。

### Bug-14　同一学号两个账号都能认证通过
- **现象**：两个账号填同一学号都审核通过。
- **根因**：认证提交只查「本人是否有 PENDING」，从不跨账号查重；学号 AES-GCM 落库（随机 IV）无法直接比对。
- **修复**：加确定性哈希列 `student_no_hash`（HMAC-SHA256，迁移 **V19**），提交与审核通过时校验「同学号不能被两个账号 APPROVED」。
- **验证**：A 用学号 X 通过后，B 用 X 提交 → 409「该学号已被其他账号认证」。

### Bug-18 / 评价计数　撤销的差评仍计入「收到的评价」
- **现象**：撤销一条差评后，「收到的评价」仍显示 2、好评率 100%（口径矛盾）；且找不到评价入口。
- **根因**：`MeStatsService` 计数用 `countByRevieweeId`（含 voided），好评率用 voided-false；入口链接指向不展示评价的信用页。
- **修复**：计数改为排除 voided（与好评率一致）；「收到的评价」入口指向评价/申诉页。
- **验证**：撤销后计数 -1；入口可达评价列表。

### Bug-16　学生认证被驳回后找不到重新提交入口
- **现象**：认证被驳回后，认证页仍显示「审核中」，看不到重新提交表单。
- **根因**：页面用本地 store 的 verifyStatus 判断，驳回后 store 不更新。
- **修复**：改用后端 `me.verifyStatus` 驱动表单显隐并回写 store。
- **验证**：admin 驳回后，该用户进认证页可重新提交。

### Bug-10/11/12/13/15　后台与通知体验
- **现象**：封禁/驳回用浏览器原生弹窗、解封/设管理员无确认、证件照只有 72px、非跳转通知只能手动标已读。
- **修复**：统一**应用内 Dialog 组件**替换 `prompt/alert/confirm` + 危险操作二次确认；缩略图加**灯箱**看原图；通知**点击即已读**。
- **验证**：四个后台页与通知页逐项手测通过。

### Bug-20　二手「联系卖家」联系不了（核查结论：非代码 Bug）
- **核查**：两账号端到端实测，开会话 + 发订单卡片均成功；前端 mock 默认关闭，真实数据下通路正常。先前「联系不了」为冷启动后端未就绪的瞬时态（已自动恢复）。

### 其它演示相关 UI 修正
- 举报弹窗原生 `<select>` → 自定义 Select 组件；任务流程进度条首段连接线点亮逻辑修正；可**删除**已撤销差评/已处理申诉（软删 + 二次确认，迁移 **V20**）。

## 五、演示注意事项

- **认证是前提**：未通过校园认证的账号不能发布/接单任务；`seed-dev.sh` 造的账号与 admin 都已认证可直接用。
- **冷启动**：后端启动需约 2~30s；前端默认关闭 mock，后端就绪后页面自动恢复（无需刷新假数据）。先起后端、灌完数据再演。
- **信用门槛**：信用分 < 60 禁止发布/接单（新账号 100，正常演示不会触发）。
- **软删不影响审计**：删除撤销差评/申诉只是从本人视图隐藏，数据行保留。
- **改完后端代码必须重启**才生效（演示前确认跑的是最新代码，Flyway 会自动补迁移）。
- **AI 助手**需配置 DeepSeek key 才走真 LLM；未配置时自动规则降级，仍可演「找单」。
