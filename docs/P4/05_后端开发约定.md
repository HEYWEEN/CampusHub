## 二、Mock JWT —— 单测 / 联调拿 token 的 2 种方式

### 方式 A：单测里直接生成（推荐）

```java
@Autowired private JwtUtil jwt;
@Autowired private AuthUserRepository userRepo;

AuthUser u = userRepo.save(new AuthUser(aes.hmacIndex("13800138000"), aes.encrypt("13800138000")));
String token = jwt.generateAccessToken(u.getId(), "APPROVED");

mockMvc().perform(get("/api/tasks/123")
        .header("Authorization", "Bearer " + token))
    .andExpect(status().isOk());
```

### 方式 B：本地起服务后走真实登录链

```bash
# 1. 发送验证码（dev 固定 123456）
curl -X POST localhost:8080/api/auth/sms-codes \
     -H "Content-Type: application/json" \
     -d '{"phone":"13800138000"}'

# 2. 用验证码换 token（首次自动建账）
curl -X POST localhost:8080/api/auth/token \
     -H "Content-Type: application/json" \
     -d '{"phone":"13800138000","smsCode":"123456"}'
# → {"data":{"accessToken":"eyJ...","refreshToken":"...","verifyStatus":"GUEST"}}

# 3. 拿 access 调任何受保护接口
curl localhost:8080/api/tasks/123 -H "Authorization: Bearer eyJ..."
```

## 三、统一响应：`ApiResponse<T>`

**所有 Controller 方法返回 `ApiResponse<T>` 或 `ApiResponse<PageResponse<T>>`，绝不返回裸 entity / Map。**

```java
@PostMapping("/api/tasks")
public ApiResponse<TaskDetailVO> create(@Valid @RequestBody TaskCreateDTO dto) {
    return ApiResponse.success(taskService.create(dto));
}
```

成功示例：
```json
{"code": 0, "message": "ok", "data": {...}, "traceId": "a1b2c3d4..."}
```

失败由 `GlobalExceptionHandler` 自动包装 —— **你只管抛 `BizException`，不要在 Controller 里 try-catch**。

## 四、错误码分段（P3 §2.4，铁律）

| 范围 | 模块 | 已用举例 |
|---|---|---|
| 1xxx | 通用 | 1001 BAD_REQUEST / 1002 UNAUTHORIZED / 1004 NOT_FOUND / 1007 RATE_LIMITED |
| **2xxx** | **auth** | 2001 SMS_CODE_INVALID / 2002 CREDENTIALS_INVALID / 2003 ACCOUNT_LOCKED / 2004 PHONE_ALREADY_REGISTERED / 2005 PASSWORD_NOT_SET |
| 3xxx | user | 你来定 |
| **4xxx** | **task** | B 定（建议 4001 TASK_SELF_ACCEPT / 4002 TASK_ALREADY_ACCEPTED / 4003 TASK_ACCEPT_LIMIT / 4004 TASK_STATE_VIOLATION 等） |
| **5xxx** | **trade** | C 定 |
| 6xxx | edu | C 定 |
| 9xxx | notify | A 定（NTF-01 时） |
| **10xxx** | **credit** | D 定（建议 10001 CREDIT_NOT_ENOUGH / 10002 FREEZE_ID_INVALID / 10003 NEGATIVE_BALANCE 等） |

**抛异常：**
```java
// 1. 用通用 code
throw new BizException(ResponseCode.NOT_FOUND, "任务不存在: " + id);

// 2. 用模块自定义 code（推荐建一个 XxxErrorCode 常量类）
public final class TaskErrorCode {
    public static final int TASK_SELF_ACCEPT = 4001;
}
throw new BizException(TaskErrorCode.TASK_SELF_ACCEPT, "不能接自己发的任务", 400);
```

HTTP 状态由 `BizException` 第 3 参数决定，默认 400。常用：401（凭据无效）/ 403（权限）/ 404（不存在）/ 409（冲突）/ 422（业务规则）/ 429（限流）。

## 五、白名单 / 鉴权约定

```properties
# application.properties
campushub.security.whitelist=/api/health,/api/auth/sms-codes,/api/auth/token,/api/auth/token/password,/api/auth/token/refresh,/api/auth/register,/error
```

**任何新增的"未登录可访问"接口，必须在白名单 CSV 里加一条**（精确匹配，不通配，避免误放行子路径）。

**判定当前用户：**
```java
import com.campushub.common.util.CurrentUserHolder;

long userId = CurrentUserHolder.getUserId();              // 已登录，未登录则 IllegalStateException
String verifyStatus = CurrentUserHolder.getVerifyStatusOrNull(); // "GUEST" / "APPROVED" / ...

// 需"已认证"才能操作 → 自己 check
if (!"APPROVED".equals(verifyStatus)) {
    throw new BizException(ResponseCode.FORBIDDEN, "需完成学生证认证");
}
```

## 六、隐私字段（P3 §9.1，铁律 — 违反 = PR 直接 reject）

| 字段 | 怎么落库 | 怎么对外 |
|---|---|---|
| 手机号 | `phone_hmac` (CHAR(64)) + `phone_cipher` (VARBINARY) | `PhoneMaskUtil.mask()` → "138****1234" |
| 真实姓名 / 学号 / 身份证 | `*_cipher` VARBINARY，AES-256-GCM | **绝不下发** |
| 密码 | `password_hash` BCrypt(10) | **绝不下发，绝不打日志** |
| 证件图 | DB 只存 `sha256 JSON`，原图在 ObjectStorage | URL 仅审批工具能拿 |

**工具速查：**
```java
@Autowired AesUtil aes;
String cipher = aes.encrypt(plainPhone);  // 落库
String hmac   = aes.hmacIndex(plainPhone); // 唯一索引 / 查找
String plain  = aes.decrypt(cipher);       // 审批端解密
```

**`PublicUserVO` 是全队唯一的公开用户对象**（P3 §1.2 钉死）—— 任何返回他人信息的接口必须走它，**严禁**返回包含 `realName/studentNo` 的对象。当前 A 还没暴露 PublicUserVO（USER-03 才做），但你的接口已经可以用 `userId` 占位，后续替换。

## 七、跨模块调用 —— `*Api` interface 而非 `@Autowired ServiceImpl`

P3 §1 + P4 看板都钉死了：跨模块通信必须走 interface（位于各模块 `api/` 子包）。

### A 这边提供给你们的（**接下来 USER-01~04 之后才有完整实现，现在是占位**）：

```java
package com.campushub.user.api;

public interface UserApi {
    PublicUserVO getPublicUser(long userId);    // 列表/详情渲染用
    String getVerifyStatus(long userId);        // 部分操作要 APPROVED 才能做
}
```

### 你们要做的：

- B 在 `task/api/TaskApi.java` 暴露 `countAcceptingBy(userId)` 之类
- C 在 `trade/api/TradeApi.java` 暴露需要的
- D 在 `credit/api/CreditApi.java` 按 **P3 §5 第 136 行**真实签名暴露：
  ```java
  int  getScoreOf(long userId);
  void freeze  (long userId, int points, String bizKey);
  void unfreeze(long userId, int points, String bizKey);
  void settle  (long userId, int points, String bizKey);
  void deduct  (long userId, int delta,  ReasonCode reasonCode, String bizKey);
  ```
  ⚠️ **bizKey 幂等模型**：调用方自己构造 bizKey（例 `task:<id>:settle`），重放同 key 不重复扣。
  数据库 `credit_record.biz_id` UK 兜底（schema.sql line 169）。
  **不要**期望 freeze 返回 freezeId —— 那是过时伪代码，与 schema 不符。

**调用方写法：**
```java
@Service
public class TaskService {
    private final CreditApi credit;   // ← interface，不是 CreditServiceImpl
    public TaskService(CreditApi credit) { this.credit = credit; }

    public void publish(long publisherId, long taskId, int reward) {
        // bizKey 由调用方按"业务:实体ID:动作"构造
        credit.freeze(publisherId, reward, "task:" + taskId + ":freeze");
    }
}
```

## 八、事件发布 / 订阅（P3 §3）

事件应用 Spring `ApplicationEventPublisher`，**BEFORE_COMMIT 模式**：

```java
// 发布方（task/service/TaskServiceImpl）
applicationEventPublisher.publishEvent(new TaskCompletedEvent(taskId, payeeId, rewardPoint));

// 订阅方（credit/listener/TaskEventListener、notify/listener/TaskEventListener）
@TransactionalEventListener(phase = TransactionPhase.BEFORE_COMMIT)
public void onTaskCompleted(TaskCompletedEvent event) {
    // bizKey 由 listener 用事件里的 taskId 构造，与发布方 freeze 时镜像配对
    String bizKey = "task:" + event.taskId() + ":settle";
    creditApi.settle(event.payeeId(), event.rewardPoint(), bizKey);
}
```

事件类放 `<module>/event/` 子包，订阅 listener 放 `<module>/listener/`。

## 十一、常见坑（已踩过、已写进 bug 日志）

1. **`@Convert(converter=...)` 比 `@Enumerated(ORDINAL)` 安全** —— enum 顺序变化时 ordinal 静默错位
2. **JWT 黑名单只对 ACCESS 生效拦截，REFRESH 在 service 里自己 check** —— 拦截器路径上没有 refresh 接口
3. **`/api/health/**` 不能进白名单** —— 否则 `/api/health/me` 无法验 JWT
4. **测试里 reset 限流器** —— `SmsRateLimiter#resetForTest()` / `TokenBlacklist#resetForTest()`
5. **跨 npm 版本生成 lock 是经典陷阱**（前端 CI 那次）—— frontend/ 已加 `.nvmrc=20`

详见 `docs/P4/bug/何翌闻_2026-05-22.md`。
