# Bug 记录模板

> **使用方式：**
> 1. 复制本文件 → 重命名为 `<你的名字>_<YYYY-MM-DD>.md`（例：`陈泽昊_2026-05-21.md`）
> 2. 每个 bug **一节**（用 `##` 分隔），按本模板逐项填
> 3. 同一天碰到多个 bug 写在同一个文件里
> 4. 每周一由 C 汇总到 `docs/P4/bug/bug_summary.md`
>
> **记录原则：**
> - 出现 bug 当时就记，不要事后补（细节会忘）
> - 即使 5 分钟解决的 bug 也要记 — P4 交付物 #8 要求"含根因分析和验证结果"
> - AI 协作过程中 AI 直出但被人工修复的问题**也算 bug**，是信任度实验的原始素材
>
> ⚠️ **常见误解**：以为只有"运行时报错"才叫 bug。实际上：编译能过但逻辑错、测试通过但语义错、性能不可接受、AI 直出代码与设计文档不一致 — **全都算**。
