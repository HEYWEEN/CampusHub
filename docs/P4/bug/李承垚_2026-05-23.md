## Bug #1：违禁词命中计数随事务回滚丢失

### 📌 基本信息

| 字段 | 内容 |
|------|------|
| **发现时间** | 2026-05-23 19:00 |
| **发现人** | 李承垚 |
| **所属模块** | edu |
| **关联任务 ID** | EDU-05 |
| **严重等级** | 🟠 高（冷静期机制失效） |
| **是否 AI 协作触发** | 是 |

### 🐛 问题现象

`TutorTaskServiceTest#createTutorTask_thirdHitStartsCooldown` 失败：`NoSuchElementException`。

**复现步骤：**
1. 连续 3 次发布含「刷课」的辅导需求
2. 每次均返回 400 违禁词
3. 查 `edu_forbidden_word_hit` 表无记录

**预期行为：** 第 3 次命中后写入 `cooldown_until`
**实际行为：** 命中计数被主事务回滚

### 🔍 根因分析

- 直接原因：`recordForbiddenHit()` 与抛 `BizException` 在同一 `@Transactional` 中，异常触发回滚
- 间接原因：单测先于联调暴露；AI 初版未考虑「失败也要持久化副作用」

### 🔧 修复方案

抽取 `ForbiddenWordHitService#recordHit`，使用 `@Transactional(propagation = REQUIRES_NEW)` 独立提交命中计数。

### ✅ 验证结果

- [x] `TutorTaskServiceTest` 4 用例全绿
- [x] 全量 `mvn test` 105 用例全绿

### 🧠 经验教训

「拦截失败」类副作用（计数、审计）应使用独立事务或 outbox，不能假设与主业务同事务提交。

| **严重等级** | 🔴 阻塞（Spring 上下文无法启动） |
| **是否 AI 协作触发** | 是 |

### 🐛 问题现象

启动测试上下文失败：`Cannot assign java.sql.Timestamp to java.time.Instant`。

### 🔍 根因分析

JPQL `SET i.updatedAt = CURRENT_TIMESTAMP` 与实体 `Instant updatedAt` 类型不匹配。

### 🔧 修复方案

从 `@Modifying` 更新语句中移除 `updatedAt` 赋值，版本号递增即可保证乐观锁语义。
