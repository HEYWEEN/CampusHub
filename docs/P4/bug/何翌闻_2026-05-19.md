## Bug #1：backend/pom.xml 含 AI 编造的不存在依赖，全新环境无法编译

| 字段 | 内容 |
|------|------|

| **发现人** | 何翌闻（前端 owner，AI 协作中发现） |
| **所属模块** | backend / 基础设施 |
| **关联任务 ID** | 阻塞 INF-01 ~ 全部后端任务 |
| **严重等级** | 🔴 阻塞（任何新环境都会立即炸） |
| **是否 AI 协作触发** | **是**（早期让 AI 起 pom.xml 时，AI 编造了实际不存在的 spring-boot 版本和 artifact 名） |

### 🐛 问题现象

**`backend/pom.xml` 中存在 4 处不存在的依赖：**

| pom.xml 写的 | Maven Central 实际 |
|---|---|
| `spring-boot-starter-parent` 版本 `4.0.5` | ❌ 不存在；最新稳定版是 **3.5.3**（4.x 尚未发布） |
| `spring-boot-starter-webmvc` | ❌ 不存在；正确名是 **`spring-boot-starter-web`** |
| `spring-boot-starter-webmvc-test` | ❌ 不存在；正确名是 **`spring-boot-starter-test`** |
| `spring-boot-starter-data-jpa-test` | ❌ 不存在；`starter-test` 已涵盖 JPA 测试支持 |

**复现步骤：**
1. 在全新环境（无 `~/.m2` 缓存）拉取仓库
2. `cd backend && ./mvnw clean compile`
3. → Maven 报 `Could not find artifact org.springframework.boot:spring-boot-starter-parent:pom:4.0.5`

**预期行为：** `mvn clean compile` → `BUILD SUCCESS`
**实际行为（修复前）：** 任何新环境都会立即失败。本地能跑只是因为 `~/.m2` 历史缓存了旧 pom 的合法依赖。

**验证方式：**
- 直接查询 Maven Central Search API
  - `g:org.springframework.boot AND a:spring-boot-starter-parent` → 252 个版本，**最新 3.5.3，无 4.x**
  - `g:org.springframework.boot AND a:spring-boot-starter-webmvc` → `numFound: 0`，artifact 不存在

### 🔍 根因分析

- **直接原因**：早期让 AI 生成 pom.xml 时，AI **凭空编造**了 Spring Boot 4.x 版本号和 `webmvc` 这种"看起来更精细"的 artifact 名变体，但这些都不存在
- **间接原因**：
  1. 没有在生成后立即在干净环境验证（`mvn dependency:resolve` 或 `mvn clean compile`）
  2. 本地 `~/.m2` 早期缓存了真实可用的依赖，让"看似能跑"掩盖了 pom.xml 实际坏掉的事实
  3. P3 阶段的 AI 协作约束（详细设计层）没有覆盖到 pom.xml 等基础设施文件
- **AI 协作教训**：AI 容易在 Maven/npm artifact 命名上"自信地编造" — 它见过大量 `spring-boot-starter-*` 的模式，会按模式造出不存在的变体

### 🔧 修复方案

```diff
- <version>4.0.5</version>
+ <version>3.5.3</version>

- <artifactId>spring-boot-starter-webmvc</artifactId>
+ <artifactId>spring-boot-starter-web</artifactId>

- <artifactId>spring-boot-starter-webmvc-test</artifactId>
+ <artifactId>spring-boot-starter-test</artifactId>

- <dependency>
-     <artifactId>spring-boot-starter-data-jpa-test</artifactId>
-     <scope>test</scope>
- </dependency>
+ (删除，starter-test 已涵盖)
```

**保留未改**：`groupId` 仍是 `com.example`、`artifactId` 仍是 `demo`、应用类仍在 `com.example.demo` 包下。这部分留给 **INF-01 任务**（A 在搭骨架时统一改为 `com.campushub`，避免本次修复触发连锁修改）。

**未加 `spring-boot-starter-security`**：留给 A 在 **INF-03 SecurityConfig** 任务时一起加（避免加了 security 但没配 SecurityConfig 导致所有 endpoint 默认要鉴权，本地起不来）。

### 🧠 经验教训

1. **AI 生成 Maven/npm 依赖时极易自创变体** — `webmvc` 不是 `web`、`webmvc-test` 不是 `test` 这种"听起来对"的变体最危险
2. **本地能跑 ≠ pom 正确** — `~/.m2` 缓存能掩盖一切，必须在 CI 或干净环境验证
3. **下次 AI 写 pom 的 prompt 要写明**：
   - 显式列出允许的 artifactId 白名单（已加入 `docs/P4/03_AI使用前统一Prompt.md` §A）
   - 要求 AI 生成后立刻自查 Maven Central API（`https://search.maven.org/solrsearch/select?q=g:xxx+AND+a:yyy`）
4. **这是绝佳的 P4 信任度实验素材**：AI 直出（不存在的依赖）→ 人工审查（Maven Central 验证）→ 修复（最小变更）→ 验证（mvn compile 通过），完整闭环
