## 二、详细分工

### 🅰️ 组员 A — 基础设施 + 鉴权 + 用户体系

> **角色定位：** 平台型工程师。所有人的代码都要 import 你写的东西，因此**质量优先于速度**。

#### 负责模块

| 模块 | 包路径 | 核心交付 |
|------|------|------|
| `common/` | `com.campushub.common.*` | ApiResponse / BizException / GlobalExceptionHandler / JwtUtil / 拦截器 |
| `config/` | `com.campushub.config.*` | WebMvcConfig / SecurityConfig / JwtConfig（先不接入 Redis） |
| `auth/` | `com.campushub.auth.*` | 短信、登录、学生认证、JWT 续签、登出 |
| `user/` | `com.campushub.user.*` | 资料、隐私开关（默认开 + 审计）、PublicUserVO |

#### 对应任务 ID

`INF-01` ~ `INF-04` / `AUTH-01` ~ `AUTH-04` / `USER-01` ~ `USER-04`（见看板 §1.1、§1.2）

#### 完成标准

- [ ] `common/response/ApiResponse` 是全队唯一返回体规范
- [ ] `JwtAuthInterceptor` 放行白名单可配置（`auth/sms-codes` `auth/token` `auth/register` 等）
- [ ] `PublicUserVO` 是公开用户对象**唯一**入口，**严禁**返回包含 realName/studentNo 的对象
- [ ] 隐私字段（手机号、姓名、学号）写入数据库前走 `AesUtil` 加密 + HMAC 索引列
- [ ] 单测覆盖率 ≥ 60%；至少包含：限流命中、JWT 过期、隐私字段未脱敏的拦截

#### 协作责任

- 提供 `UserApi` interface 给其他模块（`getPublicUser(userId)`、`getVerifyStatus(userId)`）
- **W10 周末**前完成 `INF-01` ~ `INF-04`，否则全员 block
- 在团队群发布"鉴权可用"通告，标注 mock token 如何获取

### 🅱️ 组员 B — 任务核心（状态机重镇）

> **角色定位：** 业务复杂度最高的模块 owner。State 模式是 P3 强制设计，单测不全后续联调必爆。

#### 负责模块

| 模块 | 包路径 | 核心交付 |
|------|------|------|
| `task/` | `com.campushub.task.*` | 发布 / 编辑 / 抢单 / 凭证 / 确认 / 取消 / 大厅 / 详情 |
| `task/state/` | `com.campushub.task.service.state.*` | 7 个 State 类 + StateContext |
| `task/scheduler/` | `com.campushub.task.scheduler.*` | TaskTimeoutScanner（5min 精度） |
| `task/event/` | `com.campushub.task.event.*` | Accepted/Completed/Canceled/Expired 4 个事件 |

#### 对应任务 ID

`TASK-01` ~ `TASK-08`（见看板 §1.3）+ `QA-04` GitLab CI/CD + `EXP-01` 信任度实验 + `DOC-02` 演示说明

#### 完成标准

- [ ] **状态转换白名单写死在 enum**，违法转换抛 `TaskStateException`
- [ ] 抢单接口必须用 **乐观锁**（`version` 字段 + `UPDATE ... WHERE version=?`），并发 50 次只能 1 次成功
- [ ] 单测必含：自接禁止、接单上限、版本冲突、过期任务无法接单、凭证 ≤3 图 ≤300 字
- [ ] CreditApi.freeze 调用失败 → 整个发布事务回滚
- [ ] CI/CD 至少包含：mvn test / mvn package / 代码静态检查（Checkstyle 或 SpotBugs 二选一）

#### 协作责任

- **依赖 D 的 `CreditApi`**：若 D 延迟，可向 D 索要 stub 实现先跑通
- **发布事件给 D 的 listener**：`TaskCompletedEvent` 一定要在 commit 前发，由 listener 决定是否结算
- 提供 `TaskApi` interface 给 trade/edu（`countAcceptingTaskBy(userId)` 等）

### 🅲 组员 C — 二手交易 + 教育（含辅导） + 数据库总管

> **角色定位：** 跨业务面，且承担全队 schema.sql 维护。表结构出错全队倒霉。

#### 负责模块

| 模块 | 包路径 | 核心交付 |
|------|------|------|
| `trade/` | `com.campushub.trade.*` | 发布、上下架、议价下单、双方确认完成 |
| `edu/` | `com.campushub.edu.*` | 辅导需求发布（违禁词拦截，复用 task 状态机） |
| `resources/db/` | `schema.sql` + `migration/V*` | 30 张表全量 DDL + Flyway 增量 |

#### 对应任务 ID

`TRADE-01` ~ `TRADE-04` / `EDU-05` / `SCH-01`（见看板 §1.4）+ `EXP-02` 调试对决 + `DOC-01` Bug 日志整合

#### 完成标准

- [ ] 图片上传走 `ExifCleaner` 清洗 EXIF；测试中含一张带 GPS 的样图，验证清洗后 GPS 为空
- [ ] 二手商品 9 图 + 单图 5MB 上限**在 Controller 层校验**（不要等到 Service）
- [ ] 议价后下单与抢单同样用乐观锁防并发"双买"
- [ ] 辅导发布违禁词命中 → 400 + 提示 + 计数；24h 内 3 次触发冷静期
- [ ] schema.sql 任何变更必须**同步提交 Flyway 增量脚本**（V3、V4...）
- [ ] 单测覆盖率 ≥ 60%

#### 协作责任

- 维护 `docs/P4/bug/` 目录：每周一汇总各人 bug 记录，整合成 `bug_summary.md`
- 数据库变更前在群里 @所有人 + 给出 24h 评论窗口

### 🅳 组员 D — 信用 + 通知 + 跨模块订阅 + 集成测试

> **角色定位：** 系统粘合剂。CreditApi 是 task/trade 完成结算的硬依赖，**进度延迟会拖垮全队**。

#### 负责模块

| 模块 | 包路径 | 核心交付 |
|------|------|------|
| `credit/` | `com.campushub.credit.*` | CreditApi 实现 + 评价 + 信用分 Strategy |
| `notify/` | `com.campushub.notify.*` | 站内信发送 / 列表 / 已读 + 模板 |
| `*/listener/` | `com.campushub.{credit,notify}.listener.*` | 跨模块事件订阅（核心 trick：BEFORE_COMMIT） |
| 集测 | `backend/src/test/java/.../integration/` | 1 个正常流 + 2 个异常流 |

#### 对应任务 ID

`INF-06` 跨模块接口定义 / `CRD-01` ~ `CRD-04` / `NTF-01` ~ `NTF-02` / `QA-02` `QA-03` 集测 / `DOC-03` 反思日志

#### 完成标准

- [ ] `CreditApi.freeze / unfreeze / settle / getScoreOf` 4 个方法 W11 中期前完工（**绝对硬截止**）
- [ ] `credit_account.point_balance` **永远不会出现负数**（DB 层 CHECK 约束 + 应用层校验双保险）
- [ ] 信用分变更走 Strategy 模式，每个策略独立测试
- [ ] `notify` 重复触发去重：24h 内同 user + 同 type + 同 biz_id 只发 1 条
- [ ] 集测 1：注册→登录→发任务→接单→凭证→确认→评价（含信用分变化断言）
- [ ] 集测 2 × 2：未登录访问 / 重复接单 / 越权操作（任选 2）

#### 协作责任

- **W10 周末**前先发布 `CreditApi` interface（不含实现）让 B/C 能 compile
- 若实现来不及，**至少**给一个 stub（return 固定值 + log），让 B/C 不阻塞
- 集测发现的 bug **立即**通知对应 owner，不要自己改其他人模块的代码

## 三、跨模块接口契约（W10 周末前冻结）

| 提供方 | 接口 | 消费方 | 用途 |
|------|------|------|------|
| A | `UserApi.getPublicUser(userId)` | task / trade / edu | 列表 / 详情中渲染发布者 |
| A | `UserApi.getVerifyStatus(userId)` | task / trade | 部分操作需已认证 |
| B | `TaskApi.countAcceptingBy(userId)` | task 自己（接单上限） | 不要让别人调，仅供内部 |
| B | `TaskCompletedEvent` / `TaskCanceledEvent` | credit / notify | listener 订阅 |
| C | `TradeOrderCompletedEvent` | credit / notify | listener 订阅 |
| D | `CreditApi.getScoreOf(userId)` | task（发布前校验 < 60） | 信用分门槛 |
| D | `CreditApi.freeze(userId, points, bizId)` | task / trade（冻结悬赏/押金） | 返回 freezeId |
| D | `CreditApi.unfreeze(freezeId)` | task / trade（取消） | 幂等 |
| D | `CreditApi.settle(freezeId, payeeId)` | listener（事件触发） | 完成结算 |
| D | `NotifyApi.push(userId, type, params)` | listener 内部使用 | 模板化推送 |

⚠️ **接口签名变更流程：** owner 发起 → 群内 @全员 → 24h 评审 → 通过后**同时**改 OpenAPI + Java interface + 前端 TypeScript 类型。

## 四、代码评审（Code Review）规则

- **谁评谁的：** 互邻评审 → A 评 B、B 评 C、C 评 D、D 评 A
- **PR 大小：** 单 PR ≤ 400 行（不含测试），超出强制拆分
- **必备检查项：**
  - [ ] 是否有单元测试（每个新 service 方法至少 1 个用例）
  - [ ] 异常处理是否走 `BizException` 而非裸 `RuntimeException`
  - [ ] 隐私字段（手机号、姓名、学号）是否在响应中出现
  - [ ] 跨模块调用是否走 `*Api` interface 而非直接 `@Autowired ServiceImpl`
  - [ ] 是否更新了 OpenAPI / schema.sql（若涉及）
- **AI 直出代码的 PR**：必须在 PR 描述中标 `[AI-assisted]` 并附上 Prompt 摘要（与 P3 提交规范一致）
