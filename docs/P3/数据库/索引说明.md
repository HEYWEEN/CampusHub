# 核心表索引设计说明（P3 / 任务 3.2）

> 对应文件：`schema.sql`。原则来源：`01_统一规约.md` §3.5。

## 1. 设计原则摘要

| 原则 | 落地 |
| :--- | :--- |
| 逻辑外键列必索引 | `publisher_id`、`assignee_id`、`user_id`、`task_id`、`item_id`、`buyer_id`、`seller_id` 等 |
| 高频筛选组合 | `task_order(status, deadline_at)` 支撑大厅筛选 + 超时扫描 |
| 排序字段 | `task_order.created_at`、`credit_record(user_id, created_at)` 支撑分页与流水 |
| 唯一约束 | `auth_user.phone_hmac`、`user_profile.user_id`、`credit_account.user_id`、`credit_record.biz_id`、`task_review(task_id, reviewer_id)` |
| 软删除 | 本期核心表已预留 `deleted_at`；上线后若列表默认 `deleted_at IS NULL`，建议在查询侧将 `deleted_at` 纳入联合索引最右列（视执行计划再调） |

## 2. 分表说明

### 2.1 `auth_user`

- **`uk_auth_user_phone_hmac`**：登录按手机号检索时，先对规范化手机号做 HMAC 等值查询；避免可逆加密字段无法建 btree 等值索引的问题。
- **`idx_auth_user_verify_status`**：管理端按认证状态批量审核。
- **`password_hash`**：不参与索引；仅存 BCrypt 串。

### 2.2 `auth_verification`

- **`(user_id)`**：用户查询本人最新一条认证单。
- **`(status, created_at)`**：审核队列按状态 + 时间排序。
- **`idx_auth_verification_student_no_hash`**（V19 新增）：按 `student_no_hash = HMAC-SHA256(规范化学号)` 跨账号查重，防同一学号被两个账号同时认证。

### 2.3 `user_profile`

- **`uk_user_profile_user_id`**：与用户一一对应。
- **`nickname`**：昵称非唯一，仅辅助运营检索；若冲突压力大可改为前缀索引或接 ES。

### 2.4 `task_order`

- **`idx_task_order_publisher_status` / `idx_task_order_assignee_status`**：“我的发布 / 我的接单”列表。
- **`idx_task_order_status_deadline`**：任务大厅按状态 + 截止时间筛选；与超时扫描（`US-19`）共用。
- **`idx_task_order_created_at`**：默认时间倒序分页。

### 2.5 `task_attachment`

- **`task_id`**：详情页拉取附件列表。

### 2.6 `task_review`

- **`uk_task_review_task_reviewer`**：同一发布者对同一任务仅一条评价，防重复提交（与 OpenAPI 409 语义一致）。
- **`reviewee_id + created_at`**：被评价人维度统计与信用侧聚合（若后续拆宽表再评估）。

### 2.7 `credit_account` / `credit_record`

- **`uk_credit_account_user_id`**：账户与用户 1:1。
- **`credit_score`**：大厅筛选“最低信用分”时可能 JOIN；数据量上来后建议以任务搜索宽表或缓存为主，本索引为兜底。
- **`uk_credit_record_biz`**：`freeze/unfreeze/settle` 幂等防重。
- **`(user_id, created_at)`**：积分流水时间序分页。

### 2.8 `trade_item` / `trade_order`

- **`trade_item(seller_id, status)`**：卖家上下架管理列表。
- **`trade_order(buyer_id, status)` / `(seller_id, status)`**：买卖双方订单列表。
- **`trade_order(item_id)`**：从商品跳转订单、仲裁联查。

## 3. 隐私与密码存储（任务 3.2 要求）

| 字段 | 策略 |
| :--- | :--- |
| 手机号 | `phone_cipher`（AES-256-GCM）+ `phone_hmac`（查找键）；接口仅返回脱敏展示，由应用层生成，**不入库明文列** |
| 真实姓名 / 学号 / 证件号 | 仅存 `auth_verification` 密文字段；**业务表禁止冗余** |
| 密码 | **仅** `auth_user.password_hash`，算法 **BCrypt cost=10**；禁止出现在任何 API 与日志 |

## 4. 跨模块外键禁令核对

- `user_profile.user_id`、`task.publisher_id`、`credit_account.user_id` 等：**未**对 `auth_user`/`user_profile` 建 FK，符合规约 §3.3。
- `auth_verification.user_id → auth_user.id`、`task_attachment.task_id → task.id`、`task_review.task_id → task.id`、`trade_order.item_id → trade_item.id`：同模块前缀内 FK，**允许**。
