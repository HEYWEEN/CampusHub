# 任务：编写《校园互助服务平台》软件需求规格说明书 (SRS)

> Deepseek-r1

## 1. 角色设定 (Role)
你是一位拥有 10 年经验的资深软件需求工程师和高级产品经理。你精通 IEEE 830 软件需求规格说明标准，对高校学生的校园生活痛点及 O2O 业务逻辑有深刻理解。

## 2. 任务目标 (Task)
请基于提供的 **`[需求分析.md]`**（包含 AI 生成的初步 SRS 框架）和 **`[调研原始数据.md]`**（包含问卷与用户访谈真实反馈），撰写一份完整、专业、可直接交付开发与测试团队的《软件需求规格说明书 (SRS)》。

## 3. 核心约束与修改指令 (Constraints & Modifications)
- **文档基底**：严格使用 `[需求分析.md]` 中已定义的 IEEE 830 标准框架（章节编号 1.0 至 5.0）。
- **数据来源**：功能定义必须深度融合 `[调研原始数据.md]` 中的高频痛点（如信息过载、隐私担忧、资料社区需求）。
- **[关键修改] 鉴权机制重构**：
    - **禁止**使用或提及“校园统一身份认证系统 (SSO)”集成。
    - **必须**将登录方式改为 **“手机号 + 验证码注册/登录”**。
    - **必须**设计 **“人工审核的校园身份实名认证”** 环节：用户自行上传学生证/校园卡照片，后台审核通过后获得“校园认证”标签。
    - **必须**明确“后台强实名，前台弱展示”原则，禁止在前端公开展示学号、真实姓名。
- **内容补全**：SRS 框架中的空白章节（如“私信功能”、“管理员后台”）必须根据业务逻辑进行补全和细化。
- **格式要求**：输出标准 Markdown 格式，使用多级标题、表格和列表，确保排版精美。

## 4. 输出规范 (Output Specification)
请输出一份完整的 SRS 文档，包含以下标准章节：
1. **引言**：目的、范围、定义、参考资料。
2. **总体描述**：产品视角、用户特征、约束、假设与依赖（注意：依赖项中需移除校方 SSO API）。
3. **具体功能需求**：按模块（鉴权、任务、学习社区、私信、信用积分、管理员后台等）详细拆解，每条需求需包含编号、描述、优先级、输入、处理、输出、异常处理。
4. **非功能需求**：性能、安全、可用性、可维护性。
5. **需求追踪矩阵**：需求编号与用例的映射表。
