## 核心用例详细描述（3个）

### 用例 UC-01：发布互助需求

* **参与者**：学生用户（需求方）
* **前置条件**：用户已登录
* **后置条件**：需求成功发布并进入系统

#### 基本流程：

1. 用户进入“发布需求”页面
2. 输入标题、描述、分类、地点、时间、报酬
3. 点击“发布”
4. 系统校验信息合法性
5. 系统保存需求并展示

#### 替代流：

* 4a. 信息不完整 → 提示用户补充
* 4b. 内容违规 → 提交管理员审核或拒绝发布

---

### 用例 UC-02：接单并完成服务

* **参与者**：服务方用户
* **前置条件**：需求存在且未被接单
* **后置条件**：订单完成

#### 基本流程：

1. 用户浏览需求列表
2. 选择一个需求
3. 点击“接单”
4. 需求方确认
5. 双方进入“进行中”状态
6. 服务完成
7. 双方确认完成

#### 替代流：

* 4a. 需求方拒绝 → 接单失败
* 6a. 任一方取消 → 订单终止

---

### 用例 UC-03：评价与信用更新

* **参与者**：需求方 & 服务方
* **前置条件**：订单已完成
* **后置条件**：信用分更新

#### 基本流程：

1. 用户进入订单页面
2. 提交评分（1-5星）+ 评价
3. 系统记录评价
4. 系统更新信用分

#### 替代流：

* 2a. 用户未评价 → 系统提醒


# 与人工对比

### 一、 遗漏异常流

AI生成的用例遗漏了关键且常见的业务异常流

在ai的用例接单并完成服务里，AI 仅考虑了需求方拒绝和任一方取消两种极其宽泛的替代流。

遗漏了并发冲突，即如果两人同时点击接单，或者刚点接单发起人就下架的情况。并且未考虑服务方不能接自己发的单。遗漏了信用分过低或者账户被冻结的情况。
