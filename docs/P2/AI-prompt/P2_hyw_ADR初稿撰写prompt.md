# ADR 初稿撰写 Prompt

~~~markdown
本轮任务：为 CampusHub 项目撰写一条新的架构决策记录（ADR）初稿。

## 输出格式（必须严格遵守）

输出一个标准 Markdown 节块，节标题格式为 `## ADR-{编号}：{决策标题}`，内部按以下固定结构输出，**不得增删章节、不得改变顺序**：

### 状态
写：`**[待确认]**（由人工填写日期和通过方式）`

### 背景
用无序列表列出：
- 触发本次决策的业务 / 技术约束（至少 3 条）
- 团队工时、技术栈、P1 已定稿硬性决策中与本决策相关的限制
- 至少列出 2 个以上的候选方案（含本次采纳方案）

### 决策
用无序列表精确描述采纳的方案，包括：
- 核心机制（技术栈、协议、边界划定）
- 关键约定（命名规范、包位置、接口约束等）
- 明确排除的做法（用"**不引入** / **禁止**"标注）

### 理由
用有序列表给出决策理由，每条理由：
- 优先从"功能正确性 → 质量属性 → 运维成本 → 可演进性"的优先级顺序排列
- 对每个被拒绝的候选方案，给出拒绝理由（一句话，具体到"会导致什么问题"）
- 避免用"运维成本"作为唯一理由——必须有至少 1 条功能正确性或质量属性层面的论据

### 后果
分三个子项输出：
- **正面影响**：无序列表，至少 2 条
- **负面影响**：无序列表，至少 1 条，每条附"缓解措施"
- **需要关注的风险**：无序列表，至少 1 条，每条附"缓解措施"

### AI 辅助记录
输出以下固定句并停止，不要自行填写内容：
> `[待人工填写]` 请对照本节与决策正文，记录：AI 初稿内容摘要 / 直接采纳的部分 / 人工修订点（每条附修订理由）/ 人工新增内容。

---

## 约束提醒（写 ADR 时必须遵守）

1. **量化优先**：所有阈值、时限、容量数字必须与 P1/P2 已定稿文档对齐；不确定时写 `[待讨论]` 而不是编造。
2. **双向论证**：每条理由必须同时说清"避免了什么"和"获得了什么"，不能只写负面回避。
3. **可逆性标注**：在"理由"节末尾加一行说明本决策是"可逆"还是"不可逆"，并说明回退代价。
4. **不写超纲内容**：不输出"三年路线""企业级 SLA""分布式事务"等与学生团队工时无关的内容。
5. **分块输出**：先输出"状态 + 背景 + 决策"，等我确认方向后再输出"理由 + 后果 + AI辅助记录"。

## 【本次要决策的问题】

>
> - **决策编号**：ADR-00X（参考 `ADR.md` 索引确定下一个编号）
> - **决策标题**：一句话描述"采用了什么 / 不引入什么"
> - **决策背景**：触发本次决策的具体场景或需求（2-5 句话）
> - **已考虑的候选方案**：（可选）如果你已有想法，列出 2-3 个备选
> - **倾向采纳的方案**：（可选）你倾向于采纳哪个，为什么
~~~
